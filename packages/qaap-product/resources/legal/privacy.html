Privacy Notice

Effective 18 August 2026. Applies to this Qaap instance.

The operator of this server is the data controller for this deployment. Qaap is typically self-hosted: your files stay on this machine unless the operator or an AI provider integration sends them elsewhere. This notice describes the product’s default data flows. The operator may keep additional logs or backups.

1. What this instance stores

  • GitHub identity — login, display name, and OAuth tokens needed to sign you in and clone repositories you authorize.
  • Workspace files — git clones, worktrees, agent edits, and preview artifacts under this instance’s volumes.
  • Session data — conversations, agent job logs, UI preferences, and API keys you save in Settings → AI.

2. What we do not do by default

This product does not sell personal data, run advertising, or require a Qaap cloud account. There is no central Qaap SaaS receiving your repos when you use a self-hosted instance.

3. Sign-in

Sign-in uses GitHub OAuth. GitHub’s own privacy policy applies to that login. This instance receives the profile and token GitHub returns for the OAuth app the operator registered.

4. AI providers

If the operator (or you) configure a model provider, prompts and relevant code context are sent to that provider to generate agent replies. Retention, training, and subprocessors then follow that provider’s policy. Do not paste secrets you cannot share with that provider.

5. Cookies and local storage

The browser stores a session cookie or equivalent so you stay signed in, plus interface preferences (for example display language, which this product keeps in English). Clearing site data signs you out of this instance.

6. Retention and backups

Data remains until you or the operator delete the workspace, or until the instance is destroyed. Operators may keep encrypted backups of volumes (OAuth sessions and API keys can be in those archives). Ask the operator how long backups are kept.

7. Your choices

You can disconnect GitHub access from your GitHub account settings, delete files in the workspace, and ask the operator to delete your tenant data on this instance. Rights under GDPR or similar laws are exercised against the operator, because they control the server.

8. Security

Production instances require GitHub OAuth (anonymous skip-auth is refused). Agents drop to a non-root user. Isolation between two users on the same box is an operator responsibility; this product does not treat a shared instance as a public multi-tenant service by default.

9. Contact

Privacy requests for this deployment go to the operator of the server. Do not open a public issue for a suspected vulnerability; use a private GitHub security advisory on the Qaap repository.
